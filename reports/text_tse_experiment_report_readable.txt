一句话主线： 最终成功不是因为把文本更强行地注入分离器，而是把问题拆成
先无条件分离，再用文本路由。端到端文本控制分离器会掉进 passthrough/对冲陷阱；
PIT 分离器先把两个人拆开后，文本只需要做二选一，任务难度立刻降低。后续所有成功实验都围绕
“更强的 separator、更稳的 router、更抗噪的训练分布”展开。

# 任务和评价指标

## 任务定义

本项目做的是两人混音场景下的 text-cued target speaker extraction：
给定一个混音音频，以及目标说话人所说内容的文字线索，模型需要输出目标说话人的干净语音。

`mixture` + `cue text`
->
`target speech`

数据主要来自 LibriMix / Libri2Mix，16 kHz，2-speaker，min 模式。主干分离模型使用
BSRNN。集群路径长期使用：
`/share/home/maiyue/tse1/wesep-real-tse`。

## 核心指标怎么读

p0.22p0.70

指标 | 含义

SI-SNRi | 相对原混音的 SI-SNR 提升，单位 dB。越高越好；接近 0 表示几乎没分离。本文最核心指标。
oracle ceiling | separator 已经给出的两个候选里，如果总能选对那一路，能达到的最高 SI-SNRi。它衡量 separator 上限。
routing accuracy | router 是否选中了 oracle assignment 的那一路。它衡量文本路由能力。
accept | 输出 SI-SNRi 是否大于 1 dB 的比例，是一个粗略成功率。
wrong-text ablation | 把 cue 换成干扰说话人的文本后得到的 SI-SNRi。越低越说明模型真的受文本控制。

## 最容易误解的一点：路由器不直接产生 dB

当 separator 的两个候选已经固定时，router 只是在候选 0 和候选 1 之间选择。
因此只要 routing accuracy 接近 100%，最终 SI-SNRi 就会接近 oracle ceiling。
这也是为什么后期最大瓶颈逐渐变成 separator 本身，而不是 router。

# 总览：成功路线和最终结果

## 最终成功的几种方法

方法 | clean | WHAM 5 dB | WHAM 0 dB | 是否显式 ASR | 定位

SEP_LC + ASR 路由 | ~18.80 | 14.50 | 13.92 | 是 | 强基线，直观但依赖 ASR decoding
SEP_LC + MATCHER_WHAM | 18.80 | 14.53 | 14.14 | 否 | 当前最终最佳
SEP_LC + XATTN noisy router | 18.79 | 14.34 | 13.79 | 否 | 新方向，有潜力但未超过 matcher
SEP_LC + 蒸馏小 matcher | 18.40 | 13.66 | 12.59 | 否 | 小而快，但泛化不足

[表注] 目前真正成功的几条路线。单位均为 SI-SNRi dB。

## 一句话结论

- 路线 B（PIT separation + text routing）是主线成功点。
- MATCHER_WHAM 是目前最好结果。 它去掉了显式 ASR decoding，WHAM 0 dB 达到 14.14 dB，接近 oracle ceiling 14.26 dB。
- XATTN router 的价值在于证明 cross-attention 不是没用，而是必须训练在 separator-output domain 上。
- 蒸馏 student 的价值在于轻量化，缺点是对未见噪声泛化差。

# 阶段一：端到端文本直接控制分离器为什么失败

## 最初 idea

最自然的想法是：把文字 cue 编码成 embedding，再通过 cross-attention / FiLM 注入 BSRNN，
让 separator 直接输出目标说话人。这个方向看起来最“端到端”，也最像官方 speaker embedding
TSE 的文字版本。

抽象流程是：

`mixture` + `text cue`
->
`text-conditioned separator`
->
`target speech`

## 为什么这一步值得做

如果成功，系统会非常优雅：不需要先把两个人分开，也不需要后处理路由；文本直接驱动分离器。
因此 R2--R8 反复尝试了从零训练、warm-start、冻结主干、解冻、dual-target、内容损失等变体。

## 实验结果

轮次 | 设置 | oracle | interferer | accept | 结论

R2 | 从零 + FiLM + swap | -0.029 | -0.029 | 0% | 忽略文本
R3 | 从零 + contrast + 强 FiLM | -0.043 | -0.043 | 0% | 忽略文本
R4 | warm + 冻结主干 | -0.463 | -0.480 | 17.7% | 会分离但乱猜
R5 | warm + 解冻 + dual-target | -0.0002 | -0.0002 | 0% | 塌成 passthrough
R6 | warm + 冻结 + dual-target | -0.047 | -0.051 | 0.75% | cue 盲
R7 | warm + 解冻 + 内容损失 w=1 | ≈0 | -- | 0% | 内容损失太弱
R8 | warm + 解冻 + 内容损失 w=10 | ≈0 | -- | 0% | 对冲绕不过

[表注] 端到端文本条件化分离器 R2--R8 结果。

## 失败根因

这个阶段最重要的收获不是某个模型失败，而是识别出 passthrough / 对冲 陷阱。
当模型还不会根据文本判断目标是谁时，直接输出混音往往比赌错某个说话人更安全。
对于 SI-SDR、内容 MSE、CTC-to-target 这类“输出 vs target”的损失，混音是一个很容易达到的局部最优。

诊断结果显示：

- 文本 embedding 本身可分，oracle 和 interferer 文本并不是混在一起。
- cross-attention / FiLM 模块本身有响应，不同文本会导致中间调制量变化。
- 但最终音频输出变化很小，说明主干要么把调制冲掉，要么直接学 passthrough。

## 导师复述版

端到端文本控制分离器失败，不是因为文本 embedding 完全没信息，而是训练目标给不出 bootstrap 梯度。
模型在还不会听懂文本时，输出混音是一个低风险策略；一旦进入 passthrough，对调 loss 权重也很难救回来。
因此下一步必须拆任务。

# 阶段二：路线 B，PIT 分离 + 文本路由

## 核心 idea

把原任务拆成两个简单任务：

- 无条件 PIT separation： 不看文本，先把两个人分成两路。
- text routing： 用文本 cue 在两路输出中选目标。

流程变成：

`mixture`
->
`PIT separator`
->
`candidate 0, candidate 1`
->
`text router`
->
`target`

## 为什么这一步能绕过 passthrough

PIT separation 要求输出两个 clean sources，而不是一个目标。
它的训练目标天然不允许“输出混音就过关”，因此避开了端到端 TSE 的对冲陷阱。
文本路由则被降维成二选一：只要知道哪一路说的内容更像 cue，就可以选对。

## ASR 路由结果

早期 route B 使用 ASR route：两路 separator 输出分别用 wav2vec2 ASR 转录，再和 cue text 比 CER，
选择 CER 更低的一路。

在 clean test 上，ckpt150 达到：

- routed SI-SNRi：17.54 dB
- accept：99.2%
- routing accuracy：99.5%
- wrong-text ablation：-37.9 dB

## 阶段结论

这一步是项目转折点：从 R2--R8 的 ≈0 dB 直接跳到 17 dB 以上。
它证明了“文本线索是可用的”，问题在于端到端训练方式，而不是任务本身无解。

# 阶段三：去掉显式 ASR，训练 MATCHER

## 为什么要做 matcher

ASR route 很强，但它依赖显式转文字。下一步自然问题是：

能不能不先把语音转成文字，而是直接学习“语音内容”和“文本”的匹配？

这就是双塔 matcher 的动机。

## 重要澄清：这里真的去掉 ASR 了吗？

准确说：去掉的是 ASR decoding，不是完全去掉 ASR-pretrained representation。

在代码中，matcher 的音频塔仍然使用
`torchaudio.pipelines.WAV2VEC2_ASR_BASE_960H` 作为冻结特征提取器。
但是推理时不再输出文字，也不计算 CER；只输出 audio embedding，与 text embedding 做相似度。

## 模型结构

- 音频塔：冻结 wav2vec2 -> mean pooling -> projection。
- 文本塔：字符级 embedding -> BiGRU -> projection。
- 损失：batch 内 InfoNCE，正确配对为正样本，其余为负样本。

## 优劣

优点：

- 不需要显式 ASR 转录，推理链路比 ASR route 简洁。
- 在 WHAM 噪声下与 ASR route 打平或更好。
- 双塔结构可复用：同一个 matcher 可以服务不同 separator。

缺点：

- 仍依赖 wav2vec2 ASR 预训练特征，不是完全摆脱 ASR 先验。
- 双塔交互较浅，细粒度词帧对齐能力可能不如 cross-attention。
- 对口音的真实鲁棒性还没有专门 benchmark，只能根据 wav2vec2 预训练和噪声实验做推断。

# 阶段四：抗噪训练，真正把 WHAM 0 dB 做起来

## 为什么要抗噪

clean-trained separator 和 matcher 在 clean 上很好，但一加噪声就崩。
这说明噪声的主要伤害不只是 router 识别错，而是 separator 自身 oracle ceiling 大幅下降。

## separator 优化阶梯

模型 | clean | WHAM 5 dB | WHAM 0 dB | 说明

OLD nr6 / 6s | 18.30 | 13.76 / 13.54 | 12.64 / 12.54 | 早期噪声模型
BIG nr8 / 6s | 18.60 | 14.34 / 14.51 | 13.63 / 13.29 | 加深 BSRNN
LC nr8 / 10s | 18.80 | 14.53 / 14.50 | 14.14 / 13.92 | 最终 separator

[表注] separator ladder。5 dB / 0 dB 中为 matcher route / ASR route；oracle ceiling 略高。

## 关键训练策略

- 从 clean separator 续训到 real WHAM noise。
- 从 nr6 加深到 nr8，提升强噪声分离能力。
- chunk 从 6 s 加长到 10 s，让模型在低 SNR 下看到更长上下文。
- WHAM final 使用 SNR -5 到 20 dB 的更宽训练范围。

说明路由几乎已经不是主要瓶颈。

# 阶段六：Cross-attention router

## 为什么重新尝试 cross-attention

双塔 matcher 很强，但它只在最终 embedding 层做相似度。
cross-attention 的潜在优势是让 text tokens 直接 attend 到 audio frames，
可能学到更细粒度的词级/帧级对齐。

## 第一版：clean-source XATTN router

第一版训练方式是让 router 在两个 clean source 中选目标。这个设置训练简单，但评估时 router 看到的是
separator 输出，而不是 clean source，因此存在明显 domain gap。

条件 | SI-SNRi | accept | routing acc | 结论

clean eval | 9.019 | 83.0% | 83.3% | 有信号但远不够
WHAM 0 dB | 5.237 | 80.3% | 80.0% | domain gap 很明显

[表注] clean-source XATTN router 结果。

## 第二版：训练在 SEP outputs 上

关键改进：训练时也先把 mixture 送进 frozen SEP_LC，得到两个 separated candidates。
然后用 clean target source 计算两路候选的 SI-SNR，选择更好的一路作为 oracle label。

`mixture`
->
`frozen SEP_LC`
->
`candidate 0, candidate 1`
->
`oracle SI-SNR label`
->
`XATTN router`

这样训练分布和评估分布一致，解决第一版最大的 domain gap。

## 第三版：noisy SEP candidates

进一步把训练 mixture 加 WHAM train noise，SNR 在 0--5 dB 随机，训练 router 直接适应 noisy separator outputs。
这一步不是盲目多训，而是改变训练分布，让它看见最难的 0 dB/5 dB 场景。

## XATTN 的优劣

优点：

- 证明 cross-attention 有价值，只要训练分布对齐。
- noisy SEP candidates 让 WHAM 0 dB 从 13.10 提到 13.79。
- clean 上达到 oracle ceiling，wrong-text ablation 很低，说明文本控制真实存在。

缺点：

- 训练复杂，需要在线跑 frozen separator。
- 需要 early stopping；epoch 11 比 epoch 20 更好，说明盲目多训会漂移。
- 目前仍未超过简单的 MATCHER_WHAM。

# 关于口音语音鲁棒性的判断

目前项目已有噪声鲁棒性实验，但没有专门的 accent benchmark。因此只能做基于结构的判断：

- ASR route 对口音风险最高，因为它依赖完整转录和 CER。口音导致 ASR 错词时，路由可能错。
- MATCHER_WHAM 不输出文字，可能比 ASR decoding 更稳；但它仍使用 wav2vec2 ASR 预训练特征，口音偏差仍可能存在。
- XATTN router 同样使用 wav2vec2 特征，不是天然解决口音问题；不过它可以通过 noisy/accent SEP candidates 继续训练。
- Student CNN 是否抗口音最不确定，因为小模型容易学训练集捷径，需要专门数据验证。

建议后续做一个小型 accent stress test：

- 找 CommonVoice / L2-Arctic / accented LibriSpeech 子集。
- 构造两人 mixture，保留文本 cue。
- 固定 SEP_LC，比较 ASR route、MATCHER_WHAM、XATTN noisy router 的 routing accuracy。
- 分别报告 clean accent、WHAM 5 dB accent、WHAM 0 dB accent。

# 目前最有希望的优化空间

## 优先级 1：继续增强 separator

当前 MATCHER_WHAM 在 WHAM 0 dB 为 14.14 dB，而 oracle ceiling 约为 14.26 dB。
也就是说 router 只剩约 0.12 dB 空间，主要瓶颈已经是 separator。
如果想要显著超过 14 dB，优先考虑：

- 更强 separator backbone，例如 TF-GridNet、SepFormer、MossFormer 类结构。
- 更多真实噪声、更多 room/reverb augmentation。
- checkpoint averaging 或 EMA。
- train-360 扩大训练数据。

## 优先级 2：XATTN router 做 validation early stopping

noisy XATTN 的最佳 checkpoint 是 ep11，而 ep20 变差。
这说明它不适合按 epoch 最后一个 checkpoint 取结果，应该固定一个 validation set：

- 指标用 WHAM 0 dB routing accuracy 或 routed SI-SNRi。
- 每个 epoch 后评估一个小 validation subset。
- 自动保存 best checkpoint。

## 优先级 3：matcher + XATTN score fusion

当前 matcher 稳，XATTN 有额外细粒度交互信号。可以不替换 matcher，而是融合：

`score`
= `matcher_score`
+   `xattn_residual`

这条路的好处是风险低：matcher 作为强 base，XATTN 只提供修正项。
事实上 `train_xattn_router_sep.py` 里已经有类似思想：
`base_scale * base + residual`。
后续可以把 base score 直接换成 frozen MATCHER_WHAM 的分数，再只训练 residual。

## 优先级 4：Student 用混合噪声蒸馏

Student 最大短板是泛化。下一版蒸馏应加入：

- WHAM + Gaussian + babble + DNS/noise bank。
- 更宽 SNR，例如 -5 到 20 dB。
- separated-output domain 蒸馏，而不仅是 clean/noisy source audio。

## 优先级 5：口音鲁棒性训练

如果导师关心 accent，下一步最好不是直接声称“抗口音”，而是做实验：

- 先评估：ASR route vs matcher vs XATTN。
- 再训练：把 accented speech 加入 matcher / XATTN router 的训练或 fine-tune。
- 报告 routing accuracy，而不是只看 SI-SNRi，因为 separator 和 router 影响会混在一起。

# 按时间线复述给导师

可以这样讲：

- 最初尝试端到端文本条件化分离器，用 cross-attention 和 FiLM 把文本注入 BSRNN。
但 R2--R8 都接近 0 dB。诊断发现模型容易输出混音，形成 passthrough/对冲最优解。
- 因此改成路线 B：先用 PIT 做无条件两人分离，再用文本路由。这个拆解绕过 passthrough，
clean 上立刻达到约 17.5 dB，证明任务本身可行。
- ASR route 虽然强，但依赖显式转文字。于是训练双塔 matcher，用 wav2vec2 特征和字符级文本塔做 InfoNCE。
这去掉了 ASR decoding，并在 WHAM 噪声下达到最终最好结果。
- 噪声实验发现 clean-trained 模型不抗噪，瓶颈主要是 separator ceiling。因此连续做 real WHAM noise training、
加深 BSRNN、加长 chunk，最终得到 SEP_LC。
- 为了轻量化，做了 CNN student 蒸馏，证明小模型可行，但未见噪声泛化不足。
- 最后重新尝试 cross-attention router。第一版用 clean source 训练，测试在 separator output 上，有 domain gap。
改成训练时也过 SEP_LC，并用 oracle SI-SNR assignment 产生 label 后大幅提升；
再加入 noisy SEP candidates，WHAM 0 dB 提到 13.79，但仍未超过 MATCHER_WHAM。

# 最后的判断

如果这份工作要对外讲清楚，最稳的 claim 是：

本文发现 text-cued TSE 的关键难点不是文本表示不可用，而是端到端文本条件化分离器容易陷入
passthrough/对冲。将任务拆成 PIT separation + text routing 后，系统稳定成功。
在此基础上，通过 real WHAM noise training、加深 BSRNN、加长 chunk 获得强抗噪 separator；
通过 MATCHER_WHAM 去掉显式 ASR decoding，达到当前最优 WHAM 0 dB 14.14 dB；
通过 SEP-output cross-attention router 证明细粒度 text-audio 交互有潜力，但目前仍略低于双塔 matcher。
